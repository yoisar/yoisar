# REQUERIMIENTO DE AJUSTE GRAMATICAL Y SEMÁNTICO – ELIMINACIÓN DEL POSESIVO "MI/MÍO" EN PROYECTOS
**Ref.:** Corrección de voz y propiedad intelectual
**Fecha:** 2026-06-21
**Aplicación:** Obligatoria en textos, menús, títulos y descripciones de proyectos

---

## 1. Principio Fundamental (La Regla de Oro)

A partir de este momento, queda **terminantemente prohibido** utilizar los posesivos **"Mi"**, **"Mis"**, **"Mío"**, **"Mía"**, **"Míos"** o **"Mías"** para anteceder o referirse a **cualquier proyecto, sistema o aplicación** listada en mi portfolio.

La relación correcta que debo comunicar es la de **"autoría"** o **"desarrollo a cargo"**, no la de "propiedad". Para expresar esto, debo utilizar:

- **Verbos en primera persona de acción:** *"Desarrollo"*, *"Construyo"*, *"Diseñé"*, *"Estoy a cargo de"*, *"Trabajo en"*.
- **Preposición "por" + "mí":** *"hecho por mí"*, *"desarrollado por mí"*, *"construido por Yois"*.
- **Sustantivos de relación:** *"Proyectos que desarrollo"*, *"Sistemas a mi cargo"*, *"Trabajos realizados"*.

---

## 2. Aplicación por Tipología de Proyecto (Casos concretos)

| **Tipo de Proyecto** | **Ejemplo INCORRECTO (Prohibido)** | **Ejemplo CORRECTO (Obligatorio)** | **Justificación** |
| :--- | :--- | :--- | :--- |
| **Gubernamentales (CGM, Hospital)** | *"Mi sistema CGM"* / *"Mi desarrollo para el Gobierno"* | *"El sistema CGM, desarrollado por mí para la Casa de Gobierno"* / *"Sistema que construí para el Hospital Madariaga"* | El sistema es del Estado. Yo fui el contratista/desarrollador, no el dueño. |
| **Salud (App Patología)** | *"Mi aplicación de Patología"* | *"La aplicación de Patología del Hospital Madariaga, cuyo desarrollo estuve a cargo"* | El activo digital pertenece al nosocomio. |
| **Proyectos Personales (SaaS)** | *"Mi VentaRifas"* / *"Mi Distriboo"* | *"VentaRifas, plataforma que desarrollo y opero"* / *"Distriboo, proyecto SaaS construido por mí"* | Aunque soy dueño legal, semánticamente debo enfatizar el *trabajo de desarrollo* por encima de la posesión para unificar el criterio en toda la web. |
| **Proyectos para Terceros (Guajira)** | *"Mi proyecto Guajira"* | *"Guajira, proyecto de modernización frontend en el que estoy trabajando para un tercero"* | El código y el sistema son del cliente; yo solo proveo el servicio de modernización. |
| **Proyectos en Desarrollo** | *"Mi Planning Yoisar"* | *"Planning Yoisar, herramienta que estoy desarrollando actualmente"* | Uso el verbo en gerundio para mostrar acción continua. |

## 3. Impacto en las Secciones del Sitio (Correcciones forzosas)

### 3.1. En el Hero (Cabecera)
- **Texto Actual (Incorrecto):** *"Conocé mis proyectos."*
- **Texto Corregido (Obligatorio):** *"Conocé los proyectos que desarrollo."* o *"Explorá mi trabajo en software."*

### 3.2. En el Menú Hamburguesa (Bloque de Proyectos)
- **Título del Bloque (Incorrecto):** *"Mis Proyectos"*
- **Título del Bloque (Corregido):** *"Proyectos Desarrollados"* o *"Portfolio de Soluciones"* (manteniendo la coherencia i18n: *Developed Projects* / *Projetos Desenvolvidos*).
- **Listado interno:**
    - *Incorrecto:* "Mi VentaRifas"
    - *Corregido:* "VentaRifas (Activo)" – así, sin posesivo, directo al nombre de la marca.

### 3.3. En la Sección "Sobre Mí / Enfoque"
- **Incorrecto:** *"Mis proyectos abarcan desde el Gobierno..."*
- **Corregido:** *"Los proyectos que desarrollo abarcan desde sistemas gubernamentales..."* o *"He desarrollado soluciones para el Gobierno y el sector privado."*

### 3.4. En las Fichas de Portfolio (Descripciones)
- **Incorrecto:** *"Mi sistema de gestión documental para la Casa de Gobierno de Misiones."*
- **Corregido:** *"Sistema de gestión documental que desarrollé para la Casa de Gobierno de Misiones."*
- **Incorrecto:** *"Mi desarrollo aplicativo para el área de patología."*
- **Corregido:** *"Aplicativo para el área de patología del Hospital Madariaga, construido por mí para digitalizar procesos críticos."*

## 4. Excepciones Lógicas (Lo que SÍ puedo llamar "Mío")

Para evitar un exceso de corrección robótica, se establece que **sí está permitido** usar el posesivo "mi/mis" cuando me refiera a:

1. **Mi infraestructura:** (Servidores, nube, microservicios) porque es patrimonio técnico que compré y administro yo.
2. **Mis servicios:** (Desarrollo, SaaS, IA) porque son mis capacidades profesionales y oferta comercial.
3. **Mi enfoque / mi metodología:** Porque es mi forma de trabajar.

**Ejemplo permitido:** *"Ofrezco mis servicios de desarrollo e IA corriendo sobre mi propia infraestructura."* (Aquí "mis servicios" y "mi infraestructura" son correctos).  
**Ejemplo prohibido:** *"Ofrezco mis servicios para mi sistema CGM."* → Debe ser: *"Ofrezco mis servicios para el sistema CGM, que desarrollé."*

---

## 5. Impacto en la Internacionalización (i18n)

Esta corrección semántica debe trasladarse a los tres idiomas:

- **Inglés:** Reemplazar *"My projects"* por *"Projects I develop"* o *"Portfolio"*. Reemplazar *"My system"* por *"The system I built"*.
- **Portugués:** Reemplazar *"Meus projetos"* por *"Projetos que desenvolvo"*. Reemplazar *"Meu sistema"* por *"O sistema que desenvolvi"*.

**Nota:** Los nombres propios de los proyectos (VentaRifas, CGM, PortalCheck, Guajira) no se traducen ni se modifican.

## 6. Resumen de Reemplazos Léxicos (Buscar y Reemplazar conceptual)

| **Término Prohibido** | **Término Sugerido para Reemplazo** |
| :--- | :--- |
| Mi proyecto | El proyecto que desarrollo |
| Mis proyectos | Los proyectos que desarrollo / Los proyectos a mi cargo |
| Mi sistema | El sistema que construí / El sistema desarrollado |
| Mi aplicación | La aplicación desarrollada por mí |
| Mi plataforma | La plataforma que diseñé |
| Mi SaaS | El SaaS que opero / El producto SaaS que construyo |
| Mi desarrollo | El desarrollo realizado |

## 7. Criterios de Aceptación

- [ ] El 100% de las referencias a sistemas gubernamentales y de salud en la web han eliminado el posesivo "Mi/Mis".
- [ ] Las fichas de portfolio comienzan con el **nombre del proyecto** (sin posesivo) seguido del verbo en pasado o presente (*"desarrollé"*, *"estoy desarrollando"*).
- [ ] El menú hamburguesa lista los proyectos únicamente por su nombre comercial, sin prefijos posesivos.
- [ ] La sección de "Infraestructura" y "Servicios" conserva el posesivo permitido, diferenciando claramente entre *lo que poseo* (servidores/capacidades) y *lo que entrego* (código/sistemas).
- [ ] Todas las versiones traducidas (EN/PT) reflejan esta misma lógica de no-posesión.
